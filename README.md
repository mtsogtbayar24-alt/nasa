# COSMIC SHIFT · Sprint 01 · v0.2

> **Status: functional local prototype with SYNTHETIC demo images and local FITS support. NOT connected to an official SPHEREx archive. No discoveries are claimed.**

A public-facing prototype that searches a sky field (RA, Dec, FoV), displays observations across epochs with a shared display stretch, makes exploratory difference images, and flags unverified residuals.

## Quick start (3 terminals / 5 minutes on an installed Python + Node environment)

### 1. Backend (Python 3.11+ recommended)

```bash
cd backend
python -m venv .venv
source .venv/bin/activate          # Windows PowerShell: .venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python scripts/create_demo.py       # 8 clearly synthetic observations; included in this ZIP
python -m uvicorn app.main:app --reload --port 8000
```

Backend API documentation: http://localhost:8000/docs

### 2. Frontend (Node.js 20+)

```bash
cd frontend
npm install
npm run dev
```

Open **http://localhost:3000**. Demo target defaults to the illustrative WISE 0855 field. Use **Blink** to see simulated motion and **Difference** to highlight candidate signals. A second synthetic preset illustrates variable brightness near RW Aurigae.

### 3. Tests

```bash
cd backend
python -m pytest -q
```

8 tests pass in the authoring environment; the additional FITS ingestion test is skipped there because Astropy is not installed. Installing the full `requirements.txt` will enable this test. GitHub Actions runs tests with Astropy on Python 3.11.

### Coordinate formats

- Right ascension in decimal **degrees** `[0, 360)` (not hours)
- Declination in decimal **degrees** `[-90, 90]`
- Field of view in **arcminutes** `(0, 20]`
- Shareable query example: `http://localhost:3000/?ra=133.79513&dec=-7.24515&fov=5`

## Where the data comes from

`backend/data/demo/*.npz` contains deterministic **fabricated** scenes generated by `backend/scripts/create_demo.py` for testing the UI. The images are **not** NASA, WISE, SPHEREx, or any actual telescope data. The names WISE 0855 and RW Aurigae only identify illustrative sky centers. Date values in the simulated data are invented as well.

The loader also supports local 2D celestial WCS FITS (`.fits`, `.fit`, `.fits.gz`) after `astropy` is installed. Put legally obtained, compatible science-grade FITS files into `backend/data/real/`. Data source metadata comes from the FITS `TELESCOP` header. We do **not** label data as SPHEREx without provenance.

**Not yet supported:** downloading from SPHEREx archive, SPHEREx-specific multi-HDU/102-band data products, automated detector aggregation, photometric and PSF matching, propagated error maps, contaminant masks, proper motion measurements, validated discovery classification, multi-user accounts.

## Scientific validity and limitations

- Each input image is resampled onto one fixed North-up sky grid centered on the user's RA/Dec. Real FITS use Astropy TAN-WCS transforms; the NPZ demo can use a small-angle approximation when Astropy is absent.
- Blink mode uses a **shared transfer function** across epochs of a given target and band; brightness differences are not erased by per-image stretching.
- Difference images remove an approximate background median only. **There is no PSF matching, photometric zeropoint normalization, unit conversion, uncertainty propagation, saturation masking, or contamination-flag masking**.
- The candidate detector uses a heuristic robust-MAD residual threshold (>6 times estimated pixel scatter). This number is **not a significance level**: correlated noise, interpolation, PSF mismatch and variable sources can produce artifacts.
- Images with mismatched `band`, `BUNIT` or unrelated target fields cannot be compared through the API.
- `image_count` and `real_fits_count` are local files, **not** an indication of an authenticated NASA archive connection.
- FITS support targets basic 2D image HDUs with celestial WCS; mission-specific headers and cube products need a dedicated adapter.

## Mission integration gate (before claiming real SPHEREx results)

1. Verify mission-specific public release, official archive routes and redistribution policy via NASA IRSA.
2. Download an actual public SPHEREx FITS file and inspect `HDUs`, `WCS`, `DATE-OBS`, `BUNIT`, wavelength/detector metadata, uncertainties and quality flags.
3. Find at least two observations of the **same sky region and compatible spectral band**.
4. Add a product adapter that maps detector and wavelength metadata to `Epoch` records.
5. Match background + PSF, calibrate flux, propagate uncertainty and mask contamination.
6. Validate reference stars and both positive/negative injections against multiple known targets.
7. Record provenance and *negative findings* alongside successful detections.

Official starting points: [NASA SPHEREx](https://science.nasa.gov/mission/spherex/), [NASA IRSA](https://irsa.ipac.caltech.edu/), [Astropy](https://docs.astropy.org/), [Aladin Lite](https://aladin.cds.unistra.fr/AladinLite/).
